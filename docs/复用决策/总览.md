## 2. 模块划分

| 模块 | 服务 | 说明 |
|------|------|------|
| **Agent** | `services/agent` | AI Agent 核心，编排 + 工具调用 + 记忆 |

## 4. Agent 与 Knowledge 的关系

### 4.1 架构设计

```
┌─────────────────────────────────────────────────────────────────┐
│                     services/agent                               │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐         │
│  │   Agent     │    │   Memory    │    │    Tool     │         │
│  │ Orchestrator│    │  Manager    │    │  Registry   │         │
│  └──────┬──────┘    └─────────────┘    └──────┬──────┘         │
│         │                                      │                 │
│         │  Tool Call（RAG）                     │                 │
│         │  返回结果 + 置信度                     │                 │
│         │◀─────────────────────────────────────┤                 │
│         ▼                                                               │
│  Agent 判断是否需要重新检索                                              │
└─────────────────────────────────────────────────────────────────┘
                              │
                              │ HTTP 调用
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                    services/knowledge                            │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐         │
│  │  Document   │    │   Hybrid    │    │  Permission │         │
│  │  Parser     │    │   Search    │    │   Filter    │         │
│  └─────────────┘    └─────────────┘    └─────────────┘         │
│                            │                                     │
│                            ▼                                     │
│                   返回：结果 + 置信度                               │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 检索策略控制

| 设计 | 说明 |
|------|------|
| **控制权** | Agent 拥有检索策略控制权 |
| **RAG API** | 返回 `结果 + 置信度` |
| **Agent 决策** | Agent 根据置信度判断是否需要重新检索 |
| **重检索触发** | Agent 通过 Tool 调用发起新一轮检索 |

### 4.3 为什么不合并

| 原因 | 说明 |
|------|------|
| 职责分离 | Agent 专注编排决策，Knowledge 专注检索能力 |
| 独立演进 | 两者可以独立迭代，不互相影响 |
| 服务化 | Knowledge 可以作为独立 RAG 服务供其他系统调用 |
| 扩展性 | 后续可以接入其他 Agent（如外部 Agent） |

## 7. 实施顺序

```
阶段一：shared/ 基础（1-2天）
├── 统一 AI 调用层
└── 通用组件（Redis、异步、链路追踪）

阶段二：services/knowledge（3-5天）
├── MinIO + ES 基础
├── 文档上传/解析
├── RAG 查询 API（含置信度）
└── OrgTag 权限过滤

阶段三：services/agent（3-5天）
├── LlmClient + Spring AI 集成
├── ReAct Agent 循环
├── ToolRegistry + KnowledgeTool
└── SSE 流式输出

阶段四：services/community（5-7天）
└── 文章/评论/用户系统
```
